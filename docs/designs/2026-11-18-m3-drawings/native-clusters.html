Native Clusters: Which Milestone Builds Them?

A native cluster is one hephaestus authors itself instead of importing from git (core design §5.4, your call of 2026-11-14). Example below: a cluster lab on Talos 1.12.11, endpoint https://lab.k8s.example:6443. Each option shows how you would create it; the highlighted box says what you get.

What A Native Cluster Needs (Core Design §5.4, §5.5)

  • Create: name, Talos version, endpoint, and a schematic chosen with the extension picker (P3.3).
  • Bundle: hephaestus generates the cluster secrets and the 1Password writer stores them in a fixed item layout. A failed write rolls back what it created.
  • Edit: raw YAML, then each host's redacted diff. Saving after the diff is the approval, and it is audit-logged.
  • Export: a Topf repo holding only ref+op:// references, for bootstrap and day 2 from your laptop.

home-ops is a git-imported cluster (D16, D23), so the first install in M3 needs none of this.

M3b, As CLI Commands

Creating lab

  • hephaestus cluster create lab --talos-version 1.12.11 --endpoint https://lab.k8s.example:6443 --schematic schematic.yaml
  • hephaestus cluster edit lab --file lab.yaml prints each host's redacted diff; --approve <diff id> saves it
  • hephaestus cluster export lab ./lab-topf
Usable before the UI. M4's pages call the same functions later.
~13tasks for M3b (est., up from ~8)
