/config Delivered But Not Recorded

Found by design-gate pass 2 and checked in code. /config writes the body first, then consumes the ticket and moves the machine assigned → installing in one transaction. If that transaction fails after the body went out, the design said the admin runs machine mark-installed. But mark_installed only leaves installing or install-unconfirmed (internal/fleet/transition.go:173-174), so from assigned it is refused.

Today's Design, Example talos-04-wrk

  1. Talos fetches /config; the body is fully written
  2. ↓ in those milliseconds: the database fails, or an admin action revokes the ticket
  3. The recording transaction fails → machine stays assigned; alert "config delivered but not recorded"
  4. ↓ Talos installs, reboots, network-boots first
  5. Row 10 → install script with talos.halt_if_installed=1 → Talos halts (70 min, then again). mark-installed is refused from assigned.
A · recommended

Record The Delivery; Recover With Existing Commands

  1. A revoked ticket no longer blocks recording: the body was delivered, so the ticket is consumed and the machine moves to installing as long as it is still assigned to the same host
  2. The transaction is retried once before the alert
  3. Left over only if the database is down or the admin unassigned or rebound it in that instant: alert, and the runbook is machine unassign then machine adopt … <cluster>/<host> (both exist)
  • No new transition; the core state table is unchanged
  • The common race (a cluster approval mid-write) records normally
  • Adopt stores the current render's hash; if a cluster approval raced, the node runs the older pair's config. The alert says so
B

Add A New Edge: assigned → installed

  1. Recording stays strict (a revoked ticket fails it)
  2. New admin trigger "mark installed: config delivered" from assigned straight to installed
  3. Runbook: one command after the alert
  • One-command recovery
  • Changes the core state table, and the race case is more common, because any revocation fails recording
  • Lets an admin mark a never-installed machine installed by mistake; row 6 then serves it exit for good

In both options the audit write is best effort (it cannot succeed when the database is the failure); the log line and the counter always happen.
