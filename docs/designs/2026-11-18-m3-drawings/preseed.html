Talos Preseed: Which Milestone Builds It?

Your request: keep the latest patch of the three newest Talos minors cached for amd64 and arm64, plain schematic (no extensions). A new patch replaces the old one; a new minor drops the oldest. Your two uses: boot any machine into Talos maintenance mode on demand, and install with nothing to fetch at approval.

Boot assets: about 100 MB amd64 and 92 MB arm64 per version (measured on v1.12.11), about 580 MB in all. v1.15.0-beta.0 is left out as a pre-release (my call). A timer polls /versions over TLS 1.3 to notice new patches and minors.

The Two Uses

  1. Maintenance boot: hephaestus boot-next set 52:54:00:e2:e0:03 talos-1.14 → row 3 boots v1.14.6's kernel and initramfs with no talos.config → Talos waits in maintenance mode for talosctl apply-config --insecure. A new boot-next target beside the utilities. Needs only the boot assets.
  2. Install with nothing to fetch: a host whose cluster uses the plain schematic at a preseeded version is assets_ready the moment it is approved. Needs the boot assets and the installer image, which is served by the /v2/ mirror (M3b). A host with extensions (a different schematic) still fetches at approval.
