M3: Which Machine Commands Ship Before The UI?

The core design gives every caller of fleet.Transition to M4's UI. M3 is the first milestone that installs Talos, so some of those callers must arrive now as CLI commands, run inside the container like M2's boot-next. Every trigger below already exists and is tested in internal/fleet/transition.go; a command is a thin wrapper that M4's buttons later share. Examples use the home-ops hosts: talos-01-cp, talos-03-cp, r230-t02, talos-04-wrk, talos-05-wrk (arm64), Talos v1.12.11.

The Same In Both Options: Cluster Commands

  • hephaestus cluster import home-ops --repo <git url> --ref main --path talos --credential ref+op://homelab/gitlab-deploy/token
  • hephaestus cluster list · cluster diff home-ops (each host's redacted diff for the pending pair, and "secret values changed") · cluster approve home-ops <pair id> · cluster refresh home-ops
  • hephaestus machine list and machine show <mac|uuid>, read-only, with --json like every M2 command

Every Admin Trigger Gets A Command

talos-04-wrk's install writes to the wrong disk

  • Talos fetched /config (ticket consumed) and installed; its next /boot recorded install-unconfirmed (row 6)
  • Fix the node patch, cluster approve, run topf reset --full, then machine reinstall 52:54:00:e2:e0:03 --topf-reset-full-done → assigned
  • Reboot: the next /boot mints a new ticket and installs again
You can recover from any state at a shell, before M4 exists.
